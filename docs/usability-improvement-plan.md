# 用户试用反馈改进计划

日期：2026-11-10；代码基线：`027cf8c`。状态：**已定稿；Pi / Kimi 3.1 Pro 两轮独立评审通过，无未关闭设计问题**。讨论和原始结论见[评审记录](usability-improvement-review-k3.1-pro.md)。

后续用户明确要求去除 `known_hosts` 限制，U5 按新要求改为默认 record-only / 可选 strict，覆盖原“未采纳关闭建议”的取舍。该更新来自用户新决策，不属于此前 Pi 设计评审的结论；实际变更见 §10。

本计划已完成独立设计评审；随后按用户授权实施，实际交付和验证见 §9。设计通过不代表实现验收，不改变正在运行的测试服务或真实主机信任记录。视觉遵循 `DESIGN.md`，诊断和秘密边界沿用 `docs/debug-diagnostics-design.md`。

补充试用场景：角色绑定遗漏曾产生 `NO_TARGETS`；绑定引用清单中不存在的主机被拒绝；两台主机未信任导致连接失败，另一台完成检查但有业务 FAIL。这里的“缺少校验”指页面引导和提交前反馈不足，不宣称后端从未校验。

## 2. 产品与安全决策

1. 不改变容量含义、模板摘要、Verdict 优先级、退出码、PartialRun 拓扑语义和现有接受/幂等协议。
2. 前端反馈用于及时纠错，Go 校验仍为权威；绕过页面直接调用 API 仍须安全拒绝无效输入。
3. 草稿允许保存未完成内容。阻止推进/发布/执行不等于禁止保存草稿；仅展示字段提示不能自动改写已有值。
4. F6 根据用户后续明确要求，默认 record-only 不读取、不要求、不改写 known_hosts；strict 为可选模式，仍分别解释未知、变更、吊销和不可读。两种模式都匹配本任务在预检记录的指纹，并核对机器身份和清理归属；不自动登记信任或扫描目标。浏览器只展示服务策略，不改变服务配置。
5. 提示不输出密码、私钥、原始 SSH stderr、OwnerToken、幂等键或任意文件路径。名称按普通文本转义展示，绝不当 HTML 渲染。

## 3. U1：主机清单与绑定引导（P1）

位置：`web/src/RunPreview.tsx`，沿用 `internal/inventory/inventory.go` 解析能力，不扩展清单语法。

- 随格式切换说明：quick 支持 `node=192.0.2.10`、`node=192.0.2.10:2222`、逗号分隔，主机名可作地址且要求 ReadySpec 管理端能解析。明确 quick 不能填写 SSH 用户名；有用户名需求时切换 Ansible INI/YAML。
- INI 展示 `[all:vars]` / `ansible_user=operator` / `[all]` 与三个虚构主机示例；YAML 展示等价结构。示例中不含真实主机、用户名或凭据。示例默认只复制，替换已有输入需用户明确操作。
- 清单编辑后使“已解析”状态、绑定检查和静态预览失效；异步响应必须匹配输入 revision，旧响应不能重新启用下一步。
- 清单解析后展示主机标识、地址、端口及解析得到的用户名；不为此新增用户名来源追踪。没有用户名时明确“未设置”，提示用 INI/YAML 配置；不推断成已验证或已连接。
- 角色绑定提供已解析主机的可选列表，保留逗号输入；未知主机就地指出未匹配标识。必需角色展示最少节点要求，但完整数量/架构判定仍按执行契约进行。执行目标为零时阻止提交并说明“清单存在主机不等于已绑定角色”。
- PartialRun 不因原方案最少节点数而在前端误拒；继续沿用后端 partial 选择与静态预览规则。

验收：quick/INI/YAML 示例均由真实 parser 验证；补全/删除主机后绑定校验刷新；未知 warehouse 指向清单字段与绑定字段；零目标无法提交，静态预览无 SSH 副作用。

## 4. U2：提示、必填与一致的校验（P1）

位置：`web/src/components.tsx`、`Workbench.tsx`、`RunPreview.tsx`，Go `internal/plan`、`internal/webui/plans.go`、`preview.go`、`runs.go`。

### 4.1 字段契约

- 扩展共享 Field：必填文字标识、hint、字段 error；原生 required/aria-required 与 label 关联；错误使用 aria-invalid、aria-describedby；已有 hint 与 error 同时可读。动态必填随认证方式、模板条件变更，隐藏字段不维持失效错误。
- Workbench 优先显示模板 title/description；缺失时以参数名和已登记域类型帮助文案回退。模板 schema 的 required/default/条件约束和显式 null 三态均需保留，不能把 0/false 当空值。
- 容量说明采用 Go 当前格式：非负十进制数字 + `B/KB/MB/GB/TB/KiB/MiB/GiB/TiB`，区分大小写；数字与单位间允许空白。示例 `4 GiB`、`100 GB`。解释 GB=10^9 字节、GiB=2^30 字节；不把标称 16 GB 硬件自动改判为满足 MemTotal>=16 GB。
- 前端仅实现即时格式检查，不用浮点数复刻 Go 的精确有理数归一化/溢出判断；小数字节不可整除、int64 溢出、模板 minimum 和跨字段约束以服务端结果为准。
- 输入时显示帮助，首次 blur 或尝试推进后显示错误；修改错误字段后重新校验。点击下一步/静态校验/发布/执行时汇总错误并聚焦首个可见错误字段。草稿保存继续允许未完成值。
- 清单、角色、必需用户名/密码/私钥或 Agent 身份按当前认证配置校验；短期秘密仅本地内存处理，不提交给“参数校验”接口。

### 4.2 服务端和异步一致性

- 复用已在 `server.go` 核准的 `POST /api/v1/plans/validate` 与 `/api/v1/runs/preview`，不创建执行任务；新增可选、结构化的安全字段问题列表，沿用 `Diagnostic` 的 field/role_id/item_id/code/message，兼容旧 error 文本。UI 使用标识建立字段映射，不解析英文错误字符串。
- Go 参数错误由 typed 信息投影为固定文案，区分 REQUIRED、CAPACITY_FORMAT、CAPACITY_RANGE、UNKNOWN_HOST、NO_TARGETS 等稳定原因；不回显原输入。字段路径使用已定义 JSON Pointer，动态键要按 RFC 6901 转义。
- 部分 schema 错误无法定位到一个输入时在所属区段展示汇总，不伪造字段定位；角色/主机业务 ID 在授权视图受长度限制、转义展示。
- 参数修改后使上一轮校验通过状态失效；校验请求防抖并取消/忽略旧请求。待校验和已有错误时不得直接执行；最终提交仍调用 Manager 的既有权威校验。普通基础请求失败不能被解释为明确未接受后自动重提。
- 服务端对零执行目标的拒绝在接受记录/队列/凭据保险箱写入之前完成，共享 Manager 入口覆盖直接/委托 CLI；FullRun 和 PartialRun 均须存在至少一个有效选中执行目标。不要把其他执行期拓扑 FAIL 全部改成提交错误。
- 零目标门禁只作用于新接受。在 Store 现有幂等比较及接受临界区内，先处理已接受的同语义请求或冲突，再对新请求校验；不能用无锁的“先查再写”替代原子接受，也不能让历史已接受零目标任务在重查/同键重试时被误报 rejected。同键同语义仍返回原 Run，同键不同语义仍冲突；新请求拒绝必须走统一凭据清理。
- 具体落点为 `Store.AcceptWithCommit` 的锁内幂等分支之后、`beforeCommit` 凭据安装之前，新增独立校验；不要直接放入幂等比较之前调用的 `validateSubmission`。该顺序经第二轮代码对照确认。

验收：合法/非法单位、空值、0、false、显式 null、默认值、条件必填、嵌套字段、十进制边界、大数/小数字节、未知主机、零目标和 PartialRun；前端与 Go 合同夹具共享预期，不另引入校验框架。校验后修改值/乱序响应不能保持“可执行”。API 直接调用同样拒绝，拒绝不新增 Run、不执行 SSH、不留短期凭据。增加历史零目标 Run 的同键重试、状态查询、语义冲突和并发提交回归，确认新增校验不破坏接受/unknown 恢复语义。

## 5. U3：可读报告与历史名称（P1）

### 5.1 名称数据契约

- 不改已归档 JSON，也不为显示名称改变新报告/工件摘要。增加受现有 authorize 保护的只读 `GET /api/v1/runs/{id}/display-metadata`，通过 Store 中该 Run 的冻结 Plan 构造白名单展示元数据。
- 形状：`{run_id, plan_digest, items:[{role_id,item_id,item_name,template_name}]}`；使用 `(role_id,item_id)` 联合定位。名称优先冻结检查项 name，其次冻结 embedded template name，均缺失时显示“未命名检查项”及原 ID。不能从当前工作台草稿或当前模板注册表借用名称。
- 模板名通过冻结 template ID/version/digest 精确匹配；响应不包含完整 Plan、脚本、参数或凭据。不存在 Run 返回404，鉴权失败保持401/403；404、网络失败或响应损坏时提示名称不可用并回退 ID，不阻止已授权的权威报告读取与 JSON 下载。401/403 仍通过 `api.ts` 现有会话失效/权限错误流程处理，不吞掉鉴权错误、不新增匿名重试或绕过会话校验的下载路径。
- 两个报告入口共用名称解析和格式化模块。实时报告可在已接受获得 Run ID 后请求元数据；请求切换 Run 后旧响应不能污染新页面。重复名称不合并行，保留 ID 与角色。

### 5.2 报告内容与语义

- 第一层分开“任务执行状态”和“检查结论”：例如“部分主机执行失败（PARTIAL）”“尚不能给出完整结论（UNKNOWN）”。实时连接单独写“页面与服务连接正常”，不暗示 SSH 已连接。
- 主机行对失败展示安全诊断，例如“未开始检查：主机密钥尚未登记（HOST_KEY_UNKNOWN）”；没有 item_results 显示“未执行检查”，不能当空白或通过。
- 检查行优先名称，次要位置保留 ID、模板版本；展示“最低要求 / 实际测量 / 判定 / 下一步”。H03/H02/S04 用白名单映射，把内存、CPU、可用空间变成人类可读的对照；容量同时保留原始字节详情，说明容量与文件系统可用口径，舍入不参与判定。
- 其他模板没有可靠语义 formatter 时显示通用期望/实测证据和来源，不从任意脚本输出或模糊错误文本生成解释。未知代码保留代码及固定回退说明。HOST_KEY_CHANGED/REVOKED 与 unknown 分开行动提示。
- 按主机/按检查项、搜索名称及 ID、筛选、详情和下载一致。权威 Verdict、业务 FAIL/ERROR 区别不变；有已知 FAIL 同时有身份错误时，展示两个事实，以归档 Verdict 为准，不在浏览器另算。

验收采用合成版本的三主机场景：两台 HOST_KEY_UNKNOWN、一台 COMPLETED（内存/空间 FAIL、CPU PASS）；同时覆盖旧报告、冻结名称与当前名称不同、自定义/重复名称、缺名称、元数据404/损坏/鉴权失败、XSS 名称、切换任务竞态。两入口名称一致，下载报告语义及摘要不变。

## 6. U4：报告操作列按钮（P2）

- `RunHistory.tsx` 使用现有 button 样式和操作分组；保持语义按钮、type=button、键盘焦点，处理图标和文字基线。不额外引入组件库。
- 查看/重跑/复测/取消使用一致间距、高度与排列规则；取消保留危险语义，忙碌时禁用相关操作并说明状态。取消只在可取消状态显示，重跑继续走配置向导而非直接提交。
- 操作列单独 class，宽屏组内对齐；窄屏可换行并维持表格横向滚动，不用整个 td 的 flex 破坏表格布局。无需为四操作固定过宽屏幕。

验收：1366px、768px、375px，深浅主题、中文长文案、忙碌/终态/可取消状态；Playwright 断言按钮可见可达、操作不互相覆盖，附截图人工核对列对齐。

## 7. U5：主机身份问题的可操作提示（P1）

在 SSH 认证区域根据 system/info 展示实际策略：默认 record-only 不依赖 known_hosts，只记录首次指纹；可选 strict 才校验管理端信任库。默认观测不等于可信认证，执行和清理须在握手阶段匹配任务指纹。README 保留 strict 的可信登记流程和两种策略/环境变量说明；旧服务未报告策略时不臆测默认值。

验收：默认模式面对缺文件、空文件、损坏、不同密钥、吊销记录均连接并记录指纹，不更新文件；strict 继续拒绝 unknown/changed/revoked/缺文件。重连密钥变化时，在发送凭据前拒绝；缺少任务指纹也不进行执行或清理。配置值验证、命令行覆盖环境变量、服务实际策略和界面提示一致。不连接真实目标，不暴露秘密。

## 9. 实施记录（2026-11-10）

- U1：三种清单格式的说明和可复制示例、解析结果用户名、绑定建议与未知主机提示已接入；示例来自 `web/src/inventoryExamples.json`，Go 真实解析器直接验证同一文件。解析和预览使用输入 revision 忽略旧响应。
- U2：Field 支持必填、hint、error 和无障碍关联；参数表使用模板标题、域提示与条件必填，保留默认值/null/0/false。400ms 防抖调用权威校验并中止旧请求，错误按字段定位；草稿保存不受约束。容量前后端共用 `internal/plan/testdata/capacity.json` 合同。新接受在锁内幂等分支后拒绝零目标及缺少 SSH 用户名，未安装凭据、不落接受记录；历史同键/冲突回归保持原行为。
- U3：新增 `GET /api/v1/runs/{id}/display-metadata`，仅返回冻结名称白名单；新共享 `reportPresentation.tsx` 服务两个入口，分开执行状态/检查结论/进度连接，解释身份失败和 H02/H03/S04 的要求与测量值。大于 JS 安全整数范围的字节值不做自定义容量摘要，保留通用证据视图；显示不重算判定。元数据失败回退、401会话失效和切换任务竞态已有回归。
